# Subsystem matrix

Generated by `node recorder/replay/subsystem-matrix.ts`; do not edit (B016). A family is the engine's code for one part of vanilla
and the recorded cases that exercise it. A release is `verified` for a family when every case of the family it has replayed
in each of the family's own modes and nothing compared in its modes differed; `blocked` when what differs needs an input no
recording holds; `incomplete` when anything else differs or did not replay; `n/a` with no case. Source evidence is B007's:
every version gate of the family's native files compared in vanilla's code on both sides of its boundary. A boundary is
covered when the releases either side of it are verified: for a shared path that is its equivalence there, for a divergent
one its regression. No status here comes from a registered profile or a unit test alone.

A behaviour left out of a family's scope on purpose is listed with it and documented in docs/limitations.md; it is not counted
as verified, and nothing that differs is left out without such a line. A source finding still open in
docs/parity-dispositions.json (active, or fixed without a trace) keeps every family its scope touches incomplete, however its
replays went: the replays say no recorded case differs, the finding that the code differs where none was recorded.
